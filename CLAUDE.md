# CLAUDE.md — Suomen Sanasto (Finnish A1.2 study app)

Context for any future Claude (or human) session working in this repo.
Full user-facing details and setup steps: `README.md`.

## What this is

A static, no-build web app (plain HTML/CSS/JS, PWA, works offline) for
Chloe's Metropolia Finnish A1.2 course, shared with classmates. Five tabs:
Study (Focus words / Flashcards / Quiz / Write), Words (glossary + search +
teacher's Wordwall links), Talk (dialogues, numbers, shopping), Oral test
(26 questions), Progress (levels, device sync, voice, feedback). Credit line
"Created by LinhPham" is on Study and Progress. Keep it.

## Tech choices (and why)

- **No framework, no build step.** Don't introduce React/Next.js/a bundler
  unless Chloe explicitly asks. npm/pip registries were unreachable in the
  original build sandbox, and the current app meets the brief.
- Scripts load in order in `index.html`: config, ui, speech, srs, sync,
  feedback, words, talk, oral, progress, app (app.js calls `init()` last).
  They share globals (`state`, `app`, `SRS`, `Speech`, helpers in ui.js).
- **Routing** is hash-based (`#/study`, `#/words`, `#/talk`, `#/oral`,
  `#/progress`); study sessions are not in the hash and hide the tab bar.
- **Data** is static JSON in `data/`. `vocab.json` is generated by
  `scripts/build_vocab.py` from the glossary .docx files + `hints.json`; it
  strips trailing verb-type numbers ("soittaa 1") into a `verbType` field.
  Never hand-edit vocab.json for bulk changes: regenerate it.
- **Dialogues** (`data/conversations.json`) are ORIGINAL texts written for
  the app around chapter 1–3 glossary words. They are not copied from the
  textbook (Suomen mestari 1, copyrighted), so don't transcribe textbook
  dialogues into the app. Markup: `[word]` = glossary word as written,
  `[form](glossary entry)` = inflected form. Every marked word must resolve
  to a glossary entry (check with a small script after editing).
- **Pronunciation** = Web Speech API (`js/speech.js`), `fi-FI` voice from the
  device. No API key. Quality depends on the device's installed voices.
- **Service worker** (`sw.js`) is NETWORK FIRST with cache fallback. An
  earlier cache-first version served a mix of old and new files after a
  deploy (blank glossary page), so don't switch back. Bump `CACHE_NAME` and
  update `PRECACHE_URLS` when files are added or renamed. It skips
  cross-origin requests (Supabase, Microsoft Forms, Wordwall).
- CSS has a global `[hidden] { display: none !important; }`. Keep it: several
  components set `display` and would otherwise ignore the hidden attribute.

## Word levels (js/srs.js)

Leitner box 0–5 per word. Right → box+1, wrong → box 0, "half" (missing
ä/ö dots, or correct after a hint) → +0.5 score, box unchanged. Levels:
new (unseen), focus (seen, box 0), growing (box 1–2), almost (3–4),
mastered (5). "Focus words" mode = level focus, or last result half. Each
record stores `u` (updated ms) so device sync can merge per word (newest wins).

## Online features (all optional; everything no-ops if not configured)

Supabase project + `js/config.js`. All SQL is in `supabase/setup.sql`
(idempotent, tested on Postgres 16):
- `progress`: dashboard summary rows, anon read/write. Accepted trade-off
  (counts only); `device_id` is `acct:<username>` when a learner is linked.
- `accounts` + `account_pull` / `account_push`: name + 4-digit PIN sync.
  No table policies. Security-definer functions check a bcrypt PIN hash,
  with a 10-attempt / 15-minute lockout. The PIN is also kept in the
  device's localStorage for auto-sync (low-stakes, disclosed to Chloe).
- `feedback`: anon insert only. Read via `list_feedback(passphrase)`.
- `app_secrets` + `dashboard_check`: the dashboard passphrase lives ONLY in
  the database. `DASHBOARD_PASSPHRASE` in config.js must stay empty: that
  file is public, and a passphrase there would expose feedback emails. The old
  passphrase "score" was committed publicly, so don't reuse it.
- Feedback: if `FEEDBACK_FORM_URL` (a Microsoft Form share link) is set, the
  Feedback button opens it (Chloe chose MS Forms over Formspree on 2026-09-26;
  she gets email per response + Excel). Otherwise the built-in box saves to
  the `feedback` table.

## Working in this repo

- Preview: `python3 -m http.server 8000` from this folder.
- There's no committed test suite. The 2026-09-26 build was verified with a
  Playwright script (57 checks: every tab, study modes, half credit, PIN sync
  across two browser contexts against a fake Supabase, feedback, dashboard,
  offline reload). Re-verify with a similar script after changing core logic.
- New chapter: drop `Glossary chapter N.docx` into the course glossary folder,
  add hints for the new ids to `data/hints.json`, run `build_vocab.py`, add
  Wordwall links to `data/links.json` if the teacher shares them, bump
  `APP_VERSION` / `WHATS_NEW` in `js/app.js`.
